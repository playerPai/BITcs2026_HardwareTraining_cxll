## 1. 快速复现（Vivado）

1. 打开工程：`SingleCycleCPU\project_1\project_1.xpr`（相对本文档所在目录）
2. `Flow Navigator → SIMULATION → Run Behavioral Simulation`
3. 等待仿真自动停在 `$stop`（testbench 已设 200 万 ns 上限，足够最长的 sort16 跑完）
4. 在 **Tcl 控制台**查看 testbench 结束时自动打印：
   - 总周期数：`===== sim finished, total cycles = N =====`
   - 寄存器堆：`x0 … x31` 全部值
   - 数据存储器：前 32 字中非零的项
5. 与各 `.asm` 头部注释的期望值，或本文档「验收标准」表核对

## 2. 更换测试程序（切换 imem 内容）

`imem` 默认加载 `inst26_test.mem`（见 `CPU.v` 中 `$readmemh("inst26_test.mem", rom)`），
即打开工程直接跑的是 26 条指令全覆盖测试。要跑其他测试（如 `sort16`）：

**方法一：替换工程内的 .mem（推荐）**
1. 备份 `project_1.srcs\sim_1\new\inst26_test.mem`
2. 把 `测试程序\机器代码\sort16.mem` 复制过去并改名为 `inst26_test.mem`
3. 若工程已打开：`File → Refresh Changed Modules`（或重新打开工程）后再重新运行仿真

**方法二：改 CPU.v 中的文件名**
1. 修改 `CPU.v` 里 `$readmemh("xxxxx.mem", rom)` 的文件名
2. 把对应的 `.mem` 放进 `project_1.srcs\sim_1\new\`（工程会把该目录下的文件带入仿真工作目录）

> 通用判据：程序跑完后 PC 应停在末尾的 `pass` 死循环（`beq x0,x0,pass`），
> 说明没有误入 `fail`、没有跑飞。

## 4. 周期计数（报告用）

testbench 自带周期计数器 `cyc`（复位清零，每个时钟上升沿 +1）。读数方式：

- Tcl 打印：`===== sim finished, total cycles = N =====`
- 或波形窗口读 `/tb_cpu/cyc`

单周期设计 CPI=1，周期数 = 执行指令数，即第 1 节速查表中的数值。

## 5. 用 RARS 从 .asm 生成 .mem（仅修改测试程序时需要）

> 机器码已随仓库提供（`测试程序\机器代码\`），只做仿真**不需要**本步骤。

### 5.1 图形界面方式

1. 双击 `工具\rars1_6.jar`（RARS 为外部软件，未随仓库收录，需自备；另需安装 Java）
2. `File → Open` 打开要转换的 `.asm`
3. `Run → Assemble`（快捷键 F3）；若报错，多为写入了伪指令，检查 `指令集说明.md` 的指令清单
4. `File → Dump Memory`：**Data Segment 栏目选 `.text`，Format 选 `Hex Text`**，`Dump To File` 存为同名 `.mem`
5. 检查生成的 `.mem`：每行应是一条 32 位十六进制机器码，例如 `00500093`

### 5.2 命令行方式

```bash
java -jar 工具\rars1_6.jar a dump .text hex inst26_test.mem inst26_test.asm
```

> 说明：imem 从地址 0 开始按行加载（`rom[addr[31:2]]`），而 RARS 默认把代码链接到 0x00400000。
> **这不影响结果**：程序内部全部使用 PC 相对分支/跳转、无绝对地址引用，机器码行序即执行顺序。

## 6. 行为级校验脚本（可选，开发期回归利器）

```bash
python 工具\verify_cpu.py               # 校验全部 5 个程序
python 工具\verify_cpu.py sort16.mem     # 只校验一个
```

该脚本镜像了 `CPU.v` 的译码与数据通路逻辑，秒级输出每个测试最终的寄存器/内存与期望值比对，
输出 `ALL PASS` 即全部正确。脚本内部"到 pass 的周期数"比第 1 节速查表多 2（进入死循环的探测开销），
口径差异无需理会。

## 7. 常见问题

| 现象 | 原因与对策 |
|---|---|
| 仿真时 imem 全为 x | `.mem` 没替换对，或文件名与 `$readmemh` 不一致；检查 `project_1.srcs\sim_1\new\` 下的文件 |
| 数据段结果不对（排序乱序） | 数据基址必须是小地址（`x20` 用 `addi` 置 0），不能指望 RARS 的 `.data` 布局 |
| 仿真跑不完 | testbench 时限 `#2000000`（200 万 ns），若自己改短了会提前结束 |
| 新指令不执行 | 确认用的是 `sources_1\new\CPU.v`；同目录 `CPU_8ins_backup.v` 是旧版备份，勿混淆 |
| RARS 报 pseudo-instruction | 用到了 `li/la/bnez/j/ret`/`ecall` 等伪指令；本套 `.asm` 已全部避免 |
