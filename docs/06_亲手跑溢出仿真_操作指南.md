## 方式一：一键脚本（最快，推荐）

**第 0 步**：确认文件在位
- `liucode/sim/tb_overflow.v`、`tb_overflow_sc.v`（两个测试平台）
- `liucode/programs/overflow_test.mem`（测试程序机器码）
- `liucode/sim_overflow.tcl`（一键脚本）

**第 1 步**：打开 PowerShell / CMD，进入工程目录
```powershell
cd D:\desktop\BITcs2026_HardwareTraining_cxll\liucode
```

**第 2 步**：运行一键脚本（Vivado 2019.2 全自动：加 tb → 复制 .mem → 依次跑两个仿真 → 恢复默认 top）
```powershell
D:\vivado2019.2\Vivado\2019.2\bin\vivado.bat -mode batch -source sim_overflow.tcl
```
等几分钟（首次要编译），屏幕最后会出现两条：
```
PASS tb_overflow:    4 overflow events, 6 checked, flags/mem/x31 all correct
PASS tb_overflow_sc: 4 overflow events, flags/mem/x31 all correct
```

**看到两个 PASS = 仿真通过。** 若出现 `FAIL` 或 `$fatal`，说明实现有问题，把红色日志贴出来。

## 方式二：Vivado GUI 手动操作（想亲手点点鼠标）

**第 1 步**：打开工程
- 双击 `liucode\project\liucode_project.xpr`（或 Vivado → Open Project）

**第 2 步**：把两个 tb 加入仿真文件集（一次性）
- 菜单 **Flow → Add Sources**（或左侧 Sources 面板右键 sim_1 → Add Sources）
- 选 **"Add or create simulation sources"** → Next
- Add Files → 选 `liucode\sim\tb_overflow.v` 和 `tb_overflow_sc.v` → Finish

**第 3 步**：复制测试程序到仿真运行目录（关键！否则 $readmemh 找不到）
```powershell
Copy-Item D:\desktop\BITcs2026_HardwareTraining_cxll\liucode\programs\overflow_test.mem `
          D:\desktop\BITcs2026_HardwareTraining_cxll\liucode\project\liucode_project.sim\sim_1\behav\xsim\
```

**第 4 步**：设 tb_overflow 为仿真 top，运行
- 在 Sources 面板 **sim_1** 下，右键 `tb_overflow` → **Set as Top**
- 双击 `tb_overflow`（或菜单 Flow → Simulation → Run Behavioral Simulation）
- 仿真窗口打开后，在下方 **Tcl Console** 看输出，找到：
  ```
  PASS tb_overflow: 4 overflow events, 6 checked, flags/mem/x31 all correct
  ```
  程序用 `$finish` 自动结束。

**第 5 步**（可选）：跑单周期版
- 右键 `tb_overflow_sc` → Set as Top → 再 Run Behavioral Simulation
- 预期：`PASS tb_overflow_sc: 4 overflow events, flags/mem/x31 all correct`

**第 6 步**：结束记得把 top 改回 `tb_cpu_performance`（团队性能测试用默认 top）
- 右键 `tb_cpu_performance` → Set as Top

## 结果怎么看

| 打印内容 | 含义 |
|---|---|
| `PASS ... 4 overflow events, 6 checked` | 流水线 6 个关键指令全部核对，其中 4 条溢出正确置位 |
| `PASS ... 4 overflow events` | 单周期 4 条溢出正确置位 |
| `FAIL: PC 0x0C ... expected OVF=1` | 某条指令溢出标志不对（实现或测试有问题）|
| `$fatal` / `ERROR` | 仿真中途断言失败 |

4 次溢出来自：
1. `addi x1,x1,-1`（构造 MAX_INT 的负溢出）
2. `add x3,x1,x2`（MAX+1 正溢出）
3. `addi x3,x2,-1`（MIN-1 负溢出）
4. `sub x7,x2,x4`（MIN-10 溢出）

另外 2 个不溢出的场景（MAX-1、10+20）也被专门核对过保持 0——**正反例都测了**。

## 常见问题

**Q：报 "Cannot open file overflow_test.mem"？**
→ 说明第 3 步的复制没做（或路径不对）。检查 xsim 目录下有没有 overflow_test.mem。

**Q：Vivado 报中文路径/字符集错误？**
→ 这个工程路径是纯 ASCII（liucode），一般不会；若遇到，用方式一（我已在 `D:\desktop\ovf_sim` 验证过 ASCII 路径）。

**Q：想对比两条 PASS 之外的东西？**
→ 仿真 Log 里 `$display` 会打印最终 x31 显示器值（应为 0x7FFFFFF6）与存储结果，波形窗口里能看到 `retire_ovf`、`ovf_out` 信号逐拍变化——正是答辩要说"逐指令判断 + 粘性标志"的证据。
