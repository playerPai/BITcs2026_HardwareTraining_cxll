## 第 5 页 · 26 条指令与硬布线控制

**三类指令覆盖**：
- 运算类 17 条：R 型 9（add/sub/sll/slt/and/or/xor/srl/sra）+ I 型 8（addi/slti/andi/ori/xori/slli/srli/srai）；
- 传送类 3 条：lw（读内存写寄存器）、sw（寄存器写内存）、lui（高位立即数装载）；
- 控制类 6 条：beq/bne/blt/bge + jal/jalr。

**硬布线控制**：主控制器按 opcode 组合译码，ALU 控制按 funct3/funct7 细分，
分支与跳转在 EX 级判定。指令 ROM 与数据 RAM 分离，避免取指与访存的结构冲突。

（若老师追问"opcode/funct3/funct7"：见附录 Q&A。）

## 第 6 页 · 五级流水线数据通路

**流水线分工**：IF 取指 →（IF/ID）→ ID 译码读寄存器 →（ID/EX）→ EX 运算+分支判定 →
（EX/MEM）→ MEM 数据存取、监视值形成 →（MEM/WB）→ WB 写回、指令退休。

**退休接口（亮点）**：`valid / PC / instr` 三级同步流入 WB，
**`retire_valid / retire_pc / retire_instr` 只在指令真实退休时有效**——
这组接口把有效指令与停顿、气泡区分开，**是性能统计可信的基础**。

---

## 第 7 页 · 数据相关（RAW）解决方案

**① EX/MEM 前递（选择码 10，优先级最高）**——上一条指令结果已在 EX/MEM，
直接送回 EX 输入，不必等写回；
**② MEM/WB 前递（选择码 01）**——结果位于写回阶段时送回 EX 输入，
同时覆盖 ALU 操作数与 sw 写数据；
**③ load-use 停 1 拍**——lw 数据到 MEM 后才可用，前递来不及，此时**冻结 PC、IF/ID，
并向 ID/EX 注入气泡**。

（若老师追问"为什么 load-use 必须停"：lw 的数据到 MEM 级才从内存读出，EX 级前递源里没有它。）

---

## 第 8 页 · 控制相关与结构相关

**控制相关：EX 级解决**
- beq/bne/blt/bge 在 EX 判断，jal/jalr 同样在 EX 形成目标地址；
- redirect 时更新 PC，同时冲刷 IF/ID 与 ID/EX——**已进入流水线的两条错误路径指令失效**；
- jalr 目标使用独立加法器并清零 bit0（2 字节对齐）；
- **当前策略：静态不预测，taken 分支/跳转付出冲刷代价**（逻辑简单、时序可控、正确性易验证）。

**结构相关：设计上规避**
- 指令 ROM 与数据 RAM 分离（Harvard），IF 取指与 MEM 访存可同周期进行；
- 寄存器堆 2 读 1 写接口；同周期写回采用旁路/写穿；
- 板上数码管扫描与 CPU 步进使能分离；不使用 BRAM 与 DSP。

## 第 11 页 · 按可实现频率比较（★ 答辩高光页）

这是我们性能对比的**核心结论**，也是任务书重点核查的部分：

| | 单周期 | 流水线 |
|---|---|---|
| 可实现频率 | **66 MHz**（WNS = +0.151 ns）| **100 MHz**（WNS = +0.122 ns）|
| 时序 | 收敛 | 收敛 |
| **流水线加速比** | | **1.226 ×** |

**讲解逻辑**（三句话）：
1. 把两种 CPU 各自约束到**可达最高频率**（均时序收敛，WNS > 0）；
2. 按 `CPU 时间 = 周期数 ÷ 频率` 重算各自完成五套程序的时间；
3. **流水线比单周期快 1.226 倍**——这就是流水线"缩短关键路径→提高主频"价值的定量证明。

> 若老师问计算口径：性能 bench 的 `CLOCK_FREQ_HZ` 参数分别设为 66 MHz 与 100 MHz 重跑，
> 加速比 = 单周期 CPU 时间 ÷ 流水线 CPU 时间，完整推导见实验报告"性能分析"章节。

## 附录 · 老师高频追问与标准回答（背熟）

**Q1：为什么同频下流水线 CPI 反而高？** → 同频比较有填充、停顿、冲刷开销；流水线价值在缩短关键路径、
提高可实现频率，按各自可实现频率（66 vs 100 MHz）算 CPU 时间后流水线快 1.226 倍。

**Q2：1.226× 怎么算的？** → 性能 bench 的 `CLOCK_FREQ_HZ` 分别设为时序收敛频率（66/100 MHz）重跑，
加速比 = 单周期 CPU 时间 ÷ 流水线 CPU 时间，推导见报告性能章节。

**Q3：为什么选硬布线不选微程序？** → 组合逻辑直接译码、单周期出控制信号、路径短；
微程序多一层取微指令开销，且调试复杂。代价是扩展指令要同步改译码逻辑，我们清楚并接受。

**Q4：分支预测为什么不做？** → 选择"EX 级解决+冲刷"保证正确性优先；分支预测列为增强选项，
时间上优先做溢出判断/ILA。

**Q5：停顿和冲刷区别？** → 停顿是"下一拍不许动，保住指令"（load-use 用）；冲刷是"下一拍变 NOP，
丢弃指令"（分支跳转用）。

**Q6：x31 是什么？** → 保留为"指令结果监视器"：每退休一条有效指令把结果写入 x31，
由顶层送八位数码管显示；测试程序约定不使用 x31。

**Q7：性能数据怎么保证真实？** → 统一退休口径（retire_valid）；结果不符立即 fatal；
bench 校验 `CPU 时间 = IC × CPI × Tclk` 恒等；数据直接来自仿真输出。

**Q8：结构冒险怎么解决？** → 指令 ROM 与数据 RAM 分离（Harvard）、寄存器堆 2 读 1 写、
同拍读写写穿透；板上显示扫描与 CPU 步进分离，设计上规避。

**Q9：opcode / funct3 / funct7 的关系？** → opcode（低 7 位）定大类（如 0x33 运算 R 型、
0x13 立即数 I 型、0x63 分支）；funct3 定该类操作（分支 000=beq、001=bne）；
funct7 在兄弟指令间做最后区分（add=0000000 / sub=0100000，srl/sra 同理靠 bit5）。
对应代码 `pipe_ctrl` 的 `r_alu_func` 对 {funct7,funct3} 查表。

**Q10：你个人负责什么？** → 组长，CPU 与流水线组的架构统筹与流水线 RTL/性能优化（按实际回答）。
