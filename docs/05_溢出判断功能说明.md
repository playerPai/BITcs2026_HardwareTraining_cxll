# 附加功能：溢出判断（Overflow Detection）实现说明

> 对应任务书附加功能选项 ①"支持溢出判断"。
> 修改文件：`liucode/rtl/RV32_Pipeline.v`（五级流水线 CPU）、`liucode/rtl/RV32_CPU.v`（单周期 CPU）
> 新增文件：
> - `liucode/programs/overflow_test.asm`、`overflow_test.mem`
> - `liucode/sim/tb_overflow.v`（流水线版）、`liucode/sim/tb_overflow_sc.v`（单周期版）

---

## 〇、两种 CPU 一致性说明

**两种实现共享同一套溢出语义、同一份测试程序、同一条验证口径**：

| 项 | 单周期 RV32_CPU | 流水线 RV32_Pipeline |
|---|---|---|
| ALU 溢出检测公式 | 相同（见下） | 相同（pipe_alu） |
| 门控（只算算术指令）| `reg_we && wb_sel==00` | `reg_we_e && wb_sel_e==00` |
| retire 接口 | `retire_ovf = enable && ovf_legit` | `retire_ovf = enable && valid_w && ovf_w` |
| 粘性标志 ovf_out | 组合置位 + 复位清零 | 同 |
| 测试程序 | 同一份 overflow_test.mem | 同一份 |
| 仿真结果 | PASS（4 次溢出）| PASS（4 次溢出）|

两种 CPU 的 `x31_out` 监视器语义也一致（算术/LW/LUI 显示写回值、SW 显示存储数据等），测试程序最终 x31 均为 0x7FFFFFF6。

## 一、功能定义

对有符号加/减运算（add / sub / addi，即 ALU_ADD 与 ALU_SUB）进行**有符号溢出检测**：

| 运算 | 溢出条件 | 举例 |
|---|---|---|
| 加法 ADD | 两个操作数同号，而结果与之异号 | `0x7FFFFFFF + 1 = 0x80000000`（正溢出）|
| 加法 ADD | 两个操作数同号，而结果与之异号 | `0x80000000 + (-1) = 0x7FFFFFFF`（负溢出）|
| 减法 SUB | 两个操作数异号，而结果与 a 异号 | `0x80000000 - 10 = 0x7FFFFFF6` |

检测公式（RTL 内实现，`pipe_alu` / `alu` 相同）：
```verilog
// ADD：同号相加、结果反号 -> 溢出
ovf = ~(a[31] ^ b[31]) & (a[31] ^ y[31]);
// SUB：异号相减、结果与 a 反号 -> 溢出
ovf = (a[31] ^ b[31]) & (a[31] ^ y[31]);
```

## 二、设计实现（RV32_Pipeline.v 改动点）

### 1. `pipe_alu` 增加 `ovf` 输出（L411-464）
- ALU 原来只有 `y` 结果；现在增加 `ovf` 标志，仅在 ADD/SUB 分支计算，其余运算（逻辑、移位、slt）恒为 0。

### 2. EX 级门控：只对"算术指令"报告溢出（L186-189）
```verilog
wire ovf_e = alu_ovf_e && reg_we_e && (wb_sel_e == 2'b00);
```
- 只允许 `reg_we` 且写回 ALU 结果（wb_sel=00，即 add/sub/addi）的指令产生溢出标志；
- **lw/sw 的地址加法（无符号地址语义）不算溢出**，避免误报。

### 3. 溢出标志随有效位逐级流水（L245-251, L317, L327）
- `ovf_e_buf`：EX 级与 `valid_d` 同步，气泡/冲刷时清零；
- `ovf_m`、`ovf_w`：随 valid 逐级下行到 WB，保证不会与停顿/气泡错位。

### 4. 顶层两个新输出（L30-31）
| 端口 | 含义 |
|---|---|
| `retire_ovf` | 与 `retire_valid` 同拍：**本条退休指令是否溢出**（逐指令、微架构无关）|
| `ovf_out` | **粘性标志**：一旦发生过溢出即保持 1，直到复位（板级 led/观察友好）|

```verilog
assign retire_ovf = enable && valid_w && ovf_w;   // 逐指令
always @(posedge clk or posedge reset)            // 粘性
    if (reset) ovf_out <= 1'b0;
    else if (enable && retire_ovf) ovf_out <= 1'b1;
```

### 5. 复位清零
- reset 时 `ovf_m/ovf_w/ovf_out` 全部清零，流水线恢复后从无溢出状态开始。

## 二点五、设计实现（RV32_CPU.v 单周期改动点）

单周期没有流水线，改动更简单，语义与流水线版完全对齐：

### 1. `alu` 模块增加 `ovf` 输出（L214-248）
- 与 `pipe_alu` 完全相同的检测公式与端口。

### 2. 顶层门控（L74-78, L107-121）
```verilog
wire alu_ovf;
alu u_alu (..., .ovf(alu_ovf));
wire ovf_legit = alu_ovf && reg_we && (wb_sel == 2'b00);
```

### 3. retire 接口与粘性标志（模块末尾）
```verilog
assign retire_ovf = enable && ovf_legit;   // 单周期一条指令一拍
always @(posedge clk or posedge reset)
    if (reset) ovf_out <= 1'b0;
    else if (enable && ovf_legit) ovf_out <= 1'b1;
```

- 单周期没有 retire_valid/retire_pc 端口，testbench 改用**退休指令序号**（每周期一条，序号与程序指令一一对应）核对溢出标志，验证口径与流水线版等价。

## 三、测试程序 overflow_test.asm（5 个场景，18 条指令）

| 指令 | 场景 | 期望 OVF | 写内存 |
|---|---|---|---|
| `addi x1,x1,-1`（构造 MAX 用）| 0x80000000 + (-1) | **1**（负溢出）| — |
| `add x3,x1,x2`（MAX+1）| 0x7FFFFFFF + 1 | **1** | mem[0] = 0x80000000 |
| `add x3,x1,x2`（MAX-1）| 0x7FFFFFFF + (-1) | **0** | mem[1] = 0x7FFFFFFE |
| `addi x3,x2,-1`（MIN-1）| 0x80000000 + (-1) | **1** | mem[2] = 0x7FFFFFFF |
| `add x6,x4,x5`（10+20）| 10 + 20 | **0** | mem[3] = 30 |
| `sub x7,x2,x4`（MIN-10）| 0x80000000 - 10 | **1** | mem[4] = 0x7FFFFFF6 |

> **说明**：程序开头用 `lui x1,0x80000; addi x1,x1,-1` 构造 MAX_INT，其中第二条 addi 本身是 `0x80000000+(-1)` 的负溢出——两个 testbench 都把它作为第 4 个溢出点检查，证明检测没有遗漏。

程序以 `beq x0,x0,pass` 死循环哨兵结束（不覆盖最后一个结果）。
机器码 `overflow_test.mem` 由手工编码生成，与 asm 一一对应（可对照 `指令集说明.md` 校验）。

## 四、仿真方案

### tb_overflow.v（流水线版）
- **验证目标**（三层次，保证"不仅测到溢出，还测到不溢出"）：
  1. **逐指令断言**：退休指令按 PC（retire_pc）查表，核对 `retire_ovf` 与期望一致（6 个关键 PC，含构造 MAX 的负溢出）；
  2. **粘性标志**：出现溢出后 `ovf_out` 必须为 1；
  3. **结果正确性**：检查数据内存 mem[0..4] 与最终监视器 x31 值，证明溢出场景的截断结果正确、非溢出场景完全正常。

### tb_overflow_sc.v（单周期版）
- 单周期没有 retire_pc/retire_instr 端口，改用**退休指令序号**（每条有效指令一拍，序号与程序指令一一对应）核对 `retire_ovf`，其余断言（粘性标志、dmem、x31）与流水线版相同，保证两种 CPU 用同一套验证口径。
- 预期 4 次溢出：序号 1（构造 MAX 的 MIN-1）、3（MAX+1）、9（MIN-1）、15（MIN-10）；序号 6（MAX-1）、13（10+20）不溢出。

**运行方法**（Vivado 2019.2 命令行，ASCII 路径避免中文问题）：
```powershell
cd D:\desktop\ovf_sim
# 流水线版
xvlog -work work RV32_Pipeline.v tb_overflow.v
xelab tb_overflow -s tb_overflow_snap
xsim  tb_overflow_snap -runall
# 单周期版
xvlog -work work RV32_CPU.v tb_overflow_sc.v
xelab tb_overflow_sc -s tb_overflow_sc_snap
xsim  tb_overflow_sc_snap -runall
```

与工程集成（GUI 方式）：将 `tb_overflow`（或 `tb_overflow_sc`）设为 Simulation Top，运行 Behavioral Simulation；imem 从工程 sim 目录加载 `overflow_test.mem`。

## 六、答辩要点

- **设计思路**：在 ALU 层做有符号溢出检测（公式见上），通过"退休信号"精确暴露——`retire_ovf` 逐指令、`ovf_out` 粘性，与性能测试的 retire 口径一致；
- **为何选 ALU 层 + retire 端口**：不改变指令集（无需新增指令），对流水线三类冒险零影响，工程量小、可验证性强；
- **为何门控 wb_sel**：只有算术指令写回 ALU 结果才算溢出；lw/sw 的地址加法和 jalr 目标加法不是算术溢出——这是设计的严谨点；
- **测试策略**：溢出/非溢出双场景对照（防止"只测了正例"），内存+标志+dmem 三路互证；
- **板级扩展（可选）**：将 `ovf_out` 接到 LED 或小数点位，溢出时点亮；或利用 x31 监视器在溢出场景显示标志位。

### 常见问题

**Q：报 "Cannot open file overflow_test.mem"？**
→ 说明第 3 步的复制没做（或路径不对）。检查 xsim 目录下有没有 overflow_test.mem。

**Q：Vivado 报中文路径/字符集错误？**
→ 这个工程路径是纯 ASCII（liucode），一般不会；若遇到，用方式一（`D:\desktop\ovf_sim` 是纯 ASCII 验证目录）。

**Q：想对比两条 PASS 之外的东西？**
→ 仿真 Log 里 `$display` 会打印最终 x31 显示器值（应为 0x7FFFFFF6）与存储结果，波形窗口里能看到 `retire_ovf`、`ovf_out` 信号逐拍变化——正是答辩要说"逐指令判断 + 粘性标志"的证据。
