> 对应任务书附加功能选项"支持中断"。
> 修改文件：`liucode/rtl/RV32_Pipeline.v`（五级流水线 CPU）、`liucode/rtl/RV32_CPU.v`（单周期 CPU）
> 新增文件：

> - `liucode/sim/tb_int.v`（流水线版）、`liucode/sim/tb_int_sc.v`（单周期版）
> - `liucode/sim_int.tcl`（一键运行脚本）

---

## 〇、两种 CPU 一致性说明

中断机制在两种 CPU 中**语义完全一致**：同一个测试程序、同一个中断向量、
同样的响应/返回流程、同一条验证口径（下表）。

| 项 | 单周期 RV32_CPU | 流水线 RV32_Pipeline |
|---|---|---|
| 中断请求 | `int_req`（电平，外部拉高） | 同左 |
| 全局使能 | `int_en` | 同左 |
| 中断向量 | 参数 `INT_VECTOR`（默认 0x40） | 同左 |
| 返回地址保存 | `mepc <= pc`（本周期指令被作废） | `mepc <= pc_d`（ID 级指令被推迟） |
| 嵌套屏蔽 | `in_isr`，服务中不接受新中断 | 同左 |
| 返回指令 | `mret`（0x30200073，RISC-V 标准 M 模式返回） | 同左 |
| 返回动作 | `PC <= mepc` 且 `in_isr <= 0` | 同左 |
| 被中断指令 | 作废后**返回重新执行**（不丢失、不重复广播） | 同左 |

---

## 一、设计思路（答辩重点）

**目标**：外部中断请求到来时，CPU 暂停当前程序，跳转到固定中断向量执行
服务程序（ISR），ISR 结束后用 `mret` 返回断点继续原程序——不改变指令集
主集（只在 RV32I 之外识别标准 `mret` 编码，不占用任何已有指令），对流水线
冒险机制零影响。

**为什么中断向量定为 0x40（参数化）**：
- imem 是 256 词，低地址放主程序，0x40 起放 ISR，互不重叠；
- 仿真里由 tb 拉 `int_req` 触发，板级可接按键/外部脉冲；
- `INT_VECTOR` 是 Verilog 参数，改一处即可换地址。

**为什么用专用返回指令 `mret`**：
- RISC-V 标准中 `mret`（0x30200073）负责"从 M 模式异常/中断返回"：
  `PC <- mepc`，同时重新打开中断使能；
- 相比"用 jalr 跳到返回地址寄存器"的方案，`mret` 天然携带"结束中断服务、
  恢复可中断"的语义，且不占用通用寄存器（ISR 无需保存/恢复寄存器来存放
  返回地址）。

## 二、流水线实现（RV32_Pipeline.v）

### 1. 端口与参数
```
parameter INT_VECTOR = 32'h00000040;   // 中断向量地址
input  wire int_req,                   // 中断请求（电平）
input  wire int_en,                    // 全局中断使能
output wire [31:0] mepc_out;           // 中断返回地址（调试/观察）
```

### 2. 状态与检测（ID 级）
```
reg [31:0] mepc;     // 中断返回地址
reg        in_isr;   // 中断服务中（屏蔽嵌套）

// 响应条件：使能 && 有请求 && 未在服务中 && 无停顿 && EX 无重定向冲突
wire int_pending  = int_en && int_req && !in_isr &&
                    enable && !stall && !ex_redirect;
// mret 识别：ID 级检测标准 M 模式返回指令
wire mret_pending = valid_d && (instr_d == 32'h30200073);
```

### 3. PC 重定向（优先级：中断 > mret > 分支重定向 > 顺序）
```
wire [31:0] pc_next = int_pending  ? INT_VECTOR :
                      mret_pending ? mepc :
                      ex_redirect  ? ex_target : pc_plus4_f;
```

### 4. 反馈时序（与退休跟踪共用同一个 enable 时序块）
```
if (int_pending) begin
    mepc   <= pc_d;      // 保存被推迟指令的地址，返回后重执行它
    in_isr <= 1'b1;      // 进入服务，屏蔽嵌套
end else if (mret_pending) begin
    in_isr <= 1'b0;      // 返回主程序，恢复可中断
end
```

### 5. 冲刷
- `int_pending`/`mret_pending` 与 `ex_redirect` 一样冲刷 IF/ID 与 ID/EX
  （注入 NOP），保证被中断/被返回的指令不会误退休；
- EX 及更深的旧指令不受影响（它们先于中断点，正常完成）。

### 6. 与溢出标志、监视器的关系
- `ovf_e_buf` 在中断/返回冲刷时清零，防止把被作废指令算作溢出；
- `mret` 的 opcode（1110011）不在监视器显示表内，`default` 分支
  `monitor_we_e=0`，不会污染 x31 最后结果——**返回后 x31 保持断点处
  的最终值**（测试已验证：x31 最终=5，不是 ISR 的中间值）。

## 三、单周期实现（RV32_CPU.v）

核心逻辑与流水线版同构，只是没有流水、每周期一条指令：

```
reg [31:0] mepc;
reg        in_isr;
wire int_taken  = int_en && int_req && !in_isr && enable;
wire mret_taken = (instr == 32'h30200073) && enable && !int_taken;

always @(posedge clk or posedge reset)
    if (reset) begin mepc <= 0; in_isr <= 0; end
    else if (enable) begin
        if (int_taken) begin mepc <= pc; in_isr <= 1; end
        else if (mret_taken) in_isr <= 0;
    end

// 中断作废当前指令：写回与访存都抑制（返回后重执行，防止重复写入）
assign reg_we_eff    = reg_we   && !int_taken;
assign dmem_we_eff   = dmem_we  && !int_taken;
assign display_we_eff = display_we && !int_taken && !mret_taken;

assign pc_next = int_taken  ? INT_VECTOR : mret_taken ? mepc :
                 take_branch ? (pc + br_off) : jump ? jmp_addr : pc_plus4;
```

关键点：`int_taken` 时**本周期指令的写回/访存被抑制**——这样返回到
`mepc` 重新执行它，语义与流水线版（推迟执行）完全一致。

## 四、测试程序与验证方案

### 1. 测试程序 `int_test.mem`（已生成并验证）

| 地址 | 指令 | 说明 |
|---|---|---|
| 0x00 | `addi x1,x0,0` | 计数器清零 |
| 0x04 | `addi x2,x0,5` | 循环上限 |
| 0x08 | `addi x1,x1,1` | 循环体：x1++（中断常在此处打断） |
| 0x0C | `blt x1,x2,0x08` | x1<5 循环 |
| 0x10 | `sw x1,0(x0)` | **主程序笔迹**：mem[0]=5 |
| 0x14 | `beq x0,x0,0` | 结束哨兵（自循环） |
| 0x40 | `addi x3,x0,0x55` | **ISR**：x3=0x55 |
| 0x44 | `sw x3,4(x0)` | **ISR 笔迹**：mem[1]=0x55 |
| 0x48 | `mret` | 返回主程序 |

测试策略：主程序循环计数等待中断 → tb 在运行中拉高 `int_req` → 跳 0x40 ISR
→ ISR 留下笔迹 mem[1]=0x55 → `mret` → 主程序从断点继续数满 5 → mem[0]=5。

### 2. 断言（两个 tb 完全同口径）

| 检查项 | 期望 | 证明 |
|---|---|---|
| `mem[1]` | `0x55` | **ISR 确实被执行**（中断被响应） |
| `mem[0]` | `5` | **返回后主程序续跑完成**（mepc 正确） |
| ISR 退休/PC 经过 0x40 | 1 次 | 确认中断只进一次、mret 正确返回 |
| 最终 `x31_out` | `5` | 返回后 x31 保持主程序结果（非 ISR 值） |
| `mepc_out` | 被中断指令地址 | 返回地址保存正确（打印观察） |

### 3. 实测结果（本机已跑通，工程内 sim_int.tcl）

流水线版：
```
PASS tb_int: mem[0]=5, mem[1]=0x55, ISR x1, mepc=0x00000000, x31=5
```
单周期版：
```
PASS tb_int_sc: 中断响应 1 次, mem[0]=5, mem[1]=0x55, mepc=0x00000004, x31=5
```
> mepc 值不同是两版时序差异（流水线在 ID 级记录 pc_d、单周期记录 pc），
> 两者都正确指向"被推迟/被作废的那条指令"，返回后均成功续跑。

## 六、答辩要点

- **设计思路**：标准 RISC-V 风格——专用 `mepc` 寄存器 + 中断向量 +
  `mret` 指令；不改变 RV32I 主指令集（`mret` 是标准编码，仅追加识别），
  对流水线冒险零影响；
- **精确返回**：mepc 保存"被中断但尚未执行"的指令地址，返回后重执行它
  ——不丢失、不重复，两个 CPU 语义一致；
- **嵌套屏蔽**：`in_isr` 标志保证服务中不响应新中断，`mret` 恢复——ISR
  天然不可重入（若要支持嵌套，可将 `in_isr` 换成可叠加的保存栈）；
- **测试策略**：双笔迹互证（ISR 写 mem[1]、主程序写 mem[0]）+ x31 保持
  主程序结果 + 中断仅进一次——正面证明"打断→服务→返回→续跑"全链路；
- **板级扩展（可选）**：`int_req` 接按键（按下拉高→触发），`int_en`
  接拨码开关，`mepc_out` 可送显示调试；ISR 内可用计数器实现"每按一次
  按键，蜂鸣器/数码管变化一次"的演示。
